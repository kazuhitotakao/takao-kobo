# コンテンツ更新ガイド

作品紹介とブログはmicroCMSで管理します。公開・更新した内容は、サイト側のキャッシュが更新されたあとに反映されます。

## Works：作品紹介

APIのエンドポイントは `works`、APIの形式はリスト形式です。コード上の定義は [src/types/work.ts](../src/types/work.ts) にあります。

### 作品の基本情報

| フィールドID | 入力形式 | 内容 |
| --- | --- | --- |
| `title` | テキスト | 作品名 |
| `summary` | テキスト | 何ができる作品か、誰に向けたものかがわかる短い紹介 |
| `category` | セレクト | `個人開発` または `学習課題`。取得する値は配列 |
| `thumbnail` | 画像 | 一覧と詳細ページに表示する画像 |
| `demoUrl` | テキスト | 公開サイトやデモのURL |
| `githubUrl` | テキスト | ソースコードのURL |
| `displayOrder` | 数字 | 小さい数から表示。未設定の作品は後ろに並ぶ |

一覧は「個人開発」「学習課題」に分かれます。技術名は最大5件まで表示し、続きがある場合は「ほか○件」と表示します。

### 詳細ページの項目

| フィールドID | 表示名 / 入力形式 | 書く内容 |
| --- | --- | --- |
| `role` | 担当範囲 / テキストエリア | 自分が担当した設計・実装の範囲。制作協力があれば改行して補足 |
| `background` | 制作の目的 / テキストエリア | 誰のどのような場面を想定し、何を作ろうとしたか |
| `highlights` | 工夫した点 / リッチエディタ | 見出し3と説明文で、課題・方法・使う人にとっての良さを書く |
| `features` | 主な機能 / テキストエリア | 1行につき1つの機能 |
| `technologies` | 使用技術と役割 / テキストエリア | 技術名と、それぞれを使った目的。入力例は下記 |
| `description` | 作品の補足 / リッチエディタ | 公開状況、利用時の補足、詳しい資料へのリンクなど |

冒頭に概要・担当範囲・先頭3件の技術を表示し、本文は「制作の目的 → 工夫した点 → 主な機能 → 使用技術と役割 → 作品の補足」の順に表示します。内容がない項目は表示しません。`role` と `highlights` を追加していない既存の作品も表示できます。

### 同じ説明を繰り返さないために

各項目の役割を分けると、作品の特徴が伝わりやすくなります。

- **概要**：「どんな作品か」を一言で。
- **制作の目的**：「なぜ作ったか」を説明。
- **工夫した点**：「どう考え、どう形にしたか」を具体的に。
- **主な機能**：「何ができるか」を短く列挙。
- **使用技術と役割**：「何を、何のために使ったか」を説明。
- **作品の補足**：上の項目にない公開状況や関連資料を案内。

たとえば音楽制作の工夫を「工夫した点」に書いた場合、同じ制作経緯を「作品の補足」にも重ねて書く必要はありません。曲ごとの情報が別ページにある場合は、そのリンクをまとめて案内します。

### 使用技術の入力例

1行目は技術名を半角スペース付きの ` / ` で区切り、2行目以降は `用途：説明` と書きます。

```text
Next.js / TypeScript / microCMS
画面：Next.jsでページの表示と操作を実装
データの扱い：TypeScriptで記事や作品の項目を定義
記事の管理：microCMSで作品とブログを更新
```

技術名は一覧と詳細のラベルに、2行目以降は「使用技術と役割」の説明に使います。技術名に含まれる `/` と区別するため、区切りには前後の半角スペースを入れてください。`：` を含まない補足文も表示できます。

### 更新後に見るところ

- 一覧の短い紹介だけで、何ができる作品か伝わるか。
- 詳細ページで、目的・担当範囲・工夫が区別できるか。
- 技術名に、その用途が添えられているか。
- 画像と公開先・GitHubへのリンクが正しいか。
- スマホでも見出しや箇条書きが読みやすいか。

表示の実装は [作品一覧](../src/app/works/page.tsx)、[作品カード](../src/components/work-card.tsx)、[作品詳細](../src/app/works/[id]/page.tsx) を参照してください。

## Blog：日々の記録

APIのエンドポイントは `blogs`、APIの形式はリスト形式です。コード上の定義は [src/types/blog.ts](../src/types/blog.ts) にあります。

| フィールドID | 入力形式 | 内容 |
| --- | --- | --- |
| `title` | テキスト | 記事のタイトル |
| `summary` | テキスト | 一覧に表示する短い概要 |
| `category` | セレクト | 記事のカテゴリ。取得する値は配列 |
| `body` | リッチエディタ | 記事の本文 |
| `thumbnail` | 画像 | 詳細ページとSNS共有に使用する画像 |

一覧には1ページ10件ずつ、新しい公開日時から並びます。公開日時がない場合は作成日時を使います。カテゴリの選択肢には、公開記事で使われているカテゴリが表示されます。

本文では見出し・箇条書き・画像・リンクなどを使えます。更新後は、一覧の概要と記事本文の両方を確認してください。

表示の実装は [ブログ一覧](../src/app/blog/page.tsx)、[記事詳細](../src/app/blog/[id]/page.tsx) を参照してください。

## 下書きのプレビュー

公開前の作品・記事や、公開済みの内容を書き換えた下書きは、microCMSの編集画面の「画面プレビュー」ボタンから、実際の詳細ページの見た目で確認できます。

### 設定

1. 推測されにくい文字列（例：`openssl rand -hex 32` の結果）を用意し、`MICROCMS_PREVIEW_SECRET` としてVercelの環境変数と手元の `.env.local` に設定します。Vercelでは設定後に再デプロイすると反映されます。
2. microCMSの `blogs` と `works` それぞれで「API設定 → 画面プレビュー」を開き、遷移先URLを入力して「画面プレビューボタンを表示」をONにして保存します。`<secret>` は1で用意した文字列に置き換えます。

| API | 遷移先URL |
| --- | --- |
| `blogs` | `https://takao-kobo.vercel.app/api/draft?secret=<secret>&endpoint=blogs&id={CONTENT_ID}&draftKey={DRAFT_KEY}` |
| `works` | `https://takao-kobo.vercel.app/api/draft?secret=<secret>&endpoint=works&id={CONTENT_ID}&draftKey={DRAFT_KEY}` |

### プレビュー中の表示

ボタンを押すと、secretが合い、draftKeyで下書きを取得できたときだけプレビューが始まり、詳細ページへ移動します。プレビュー中はキャッシュを使わずに最新の下書きを表示し、本文の上に「下書きをプレビューしています」と表示されます。

「プレビューを終了」を押すか、ブラウザを閉じると通常の表示に戻ります。プレビューは開いた人のブラウザだけで有効になり、ほかの人の表示には影響しません。

実装は [プレビューの入口](../src/app/api/draft/route.ts)、[下書きの取得](../src/lib/draft.ts) を参照してください。
